# ITSMIFY

Employee and IT-asset management for the ITSMIFY service desk. The application
uses Next.js (App Router), Prisma, PostgreSQL, Persian RTL UI, and the existing
role-based authentication.

## What is implemented

- Username/password sign-in with administrator-provisioned accounts only.
- Forced temporary-password change on first sign-in.
- Employee directory with search, filters, sorting, pagination, profile view,
  create/edit, role assignment, suspension, reactivation, password reset and
  soft deletion.
- IT asset inventory for hardware, software and network assets, including
  category-specific technical details, employee assignment, return, assignment
  history, parent/component links, and maintenance/operation/inspection history.
- Real dashboard counters scoped to the signed-in role. No placeholder metrics.
- Self-service profile with organizational details and currently assigned assets.
- Jalali/Persian calendar presentation for dates; values are stored as ISO dates
  and native date inputs use the Gregorian calendar.

## Roles

| Role | Employee management | Asset read/write | Asset delete |
| --- | --- | --- | --- |
| `EMPLOYEE` | No | No | No |
| `IT_SPECIALIST` | No | Yes | No |
| `IT_MANAGER` | No | Yes | Yes |
| `SYS_ADMIN` | Yes | Yes | Yes |

The admin layout admits any role with employee-management or asset access, while
each page and API route checks its exact action on the server. Hiding navigation
items is never treated as authorization.

## Requirements

- Node.js 20 or newer
- PostgreSQL (the local development database is expected on `localhost:5432`)
- A `.env` file based on `.env.example`

## Setup

```bash
npm install
npx prisma migrate deploy
npx prisma generate
```

Create the first system administrator. Omit `--password` to generate a temporary
password that is printed once:

```bash
npm run db:admin -- \
  --first-name "System" \
  --last-name "Administrator" \
  --username "admin" \
  --phone "09121234567"
```

Start the application:

```bash
npm run dev
```

Open `http://localhost:3000` and sign in. The first sign-in is forced through the
password-change screen.

## Data and migration rules

Migrations in `prisma/migrations/` are additive. Existing users, sessions and
audit rows are preserved; the employee profile rows were backfilled for existing
users. Do not reset the database to apply this feature set.

- `User` remains the authentication identity. `EmployeeProfile` stores HR and
  organizational data one-to-one.
- `Asset` stores common inventory fields. Category-specific fields live in
  `ComputerDetail`, `MonitorDetail`, `PeripheralDetail`, `NetworkDetail` and
  `SoftwareDetail`.
- `AssetAssignment` is append-only history. A PostgreSQL partial unique index
  (`asset_assignments_one_open_per_asset`) guarantees at most one open assignment.
- Asset codes are generated by the `asset_code_seq` PostgreSQL sequence in
  `AST-00001` form. Serial numbers are indexed but intentionally not unique.
- Assign and return operations use a row lock and a transaction.
- Employee deletion is a soft delete and is blocked while assets are assigned.
- No source spreadsheet rows are imported automatically. Source columns that
  contained plaintext system or automation passwords are deliberately not stored;
  a future encrypted credential vault is the appropriate place for those secrets.
